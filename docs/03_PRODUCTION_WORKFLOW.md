# 制作手順 — 自動制作で判断を積み重ねる

作成日：2026年11月11日。対象：既存原画を使う通常の静止画クリエイターズスタンプ。

この文書は、本リポジトリで提案する制作方法であり、実装済みの処理やMuseの固有機能を説明するものではない。LINEの公式規格は [調査・出典](01_RESEARCH_AND_SOURCES.md)、配置の考え方は [デザイン資料](02_DESIGN_PLAYBOOK.md) を参照する。

## 1. 工程と成果物

| 工程 | 主な判断 | 残すもの |
|---|---|---|
| 条件整理 | 誰が誰に使うか、何が確定しているか | PACK_BRIEF |
| 原画確認 | 特徴、表情、使える空間、変更範囲 | 原画の観察メモ |
| 構成設計 | 文言、用途、感情、原画、配置 | STAMP_PLAN |
| 参考の分析 | 参考のどの効果を使うか | REFERENCE_CARD |
| 代表例の比較 | 文字、顔、一体感をどの案が両立するか | 候補画像、採用理由 |
| セット制作 | 共通性を保ちながら意味に合う変化をつける | 個別PNG、一覧 |
| 品質確認 | 規格、文字、原画、縮小、背景、重複 | REVIEW_LOG |
| 引き継ぎ | 何が良く、何を次も使うか | 完成物、未確認事項、短いルール |

毎工程でユーザーの返答を必須にしない。依頼された範囲では比較・選定・修正まで進め、仮定と判断理由を残す。原画、指定文言、変更権限などの不可欠な情報が不足しているときは、先に進められる工程と不足事項を分ける。

## 2. 条件と原画を確かめる

[PACK_BRIEF](../templates/PACK_BRIEF.md) に今回の指定を転記する。次に実際の原画を見る。ファイル名だけから表情やポーズを想像しない。

### 原画で見ること

- キャラが誰かを識別する特徴：顔の形、目、髪、耳、模様、服、線の感じ。
- 感情を伝える部分：目、口、手、体の向き、力の入り方。
- 文字を置ける場所：輪郭の外側、手や体がつくる空間、頭の上や横。
- 読み取りにくくなりそうな部分：細い線、淡い色、小さな手、透過の縁。
- 元のキャンバスと実際の絵の範囲の違い。

原画は元ファイルとして保管する。合成結果、縮小画像、プレビューを別にする。表示用の背景を敷いたプレビューと、背景透過の提出用PNGも区別する。

## 3. 使う場面から文言と感情を整理する

公式の構成案記事でも、制作前に挨拶や感情を一覧化する方法が紹介されている。参照：[LINE公式・構成案](https://note.com/line_cm/n/n2309cb7be805)（2022年7月8日）。

本リポジトリでは、[STAMP_PLAN](../templates/STAMP_PLAN.md) に各画像の役割を残す。

| 用途の例 | 考える違い |
|---|---|
| お礼 | 軽いお礼、丁寧なお礼、感激、照れ |
| 了承 | 気軽な返事、落ち着いた承諾、張り切った返事 |
| ねぎらい | 日常の労い、いたわり、休むことを勧める |
| 連絡 | 出発、到着、少し待つ、あとで返す |
| お願い・断り | 柔らかな依頼、遠慮、軽い辞退 |
| 気分の共有 | 眠い、嬉しい、驚いた、落ち込んだ |

上表は企画の観点であり、必ず全種類を入れる条件ではない。敬語限定・家族用・文字なし中心などの指定がある場合は、その作品の目的に合わせる。

### 文言が確定しているとき

指定文字列を基準データとして保持する。レイアウト案を作るために改行を加える場合は、元の文字列も別に残す。語句、句読点、感嘆符、英字表記の変更は別案とする。

### 文言も提案するとき

対象者とキャラに合う口調で案を作る。似た意味の言い換えが多い場合は、その違いが実際の使う場面に結びつくかを確認する。感情の配分に一律の正解は置かない。

## 4. 参考を選ぶ

参考は今回の課題に合うものを選び、[REFERENCE_CARD](../templates/REFERENCE_CARD.md) に「どの効果を取り入れるか」を書く。

例：長い文言の改行、文字が大きくても顔が見える構図、静かな反応の文字組み、淡いキャラが背景から分離する方法。

記事の説明だけを読んだ場合と、画像を直接見た場合を分ける。画像を見ていなければ、具体的な線・配置・配色を観察したと報告しない。参考から得た仕組みを自分の原画で試し、作品固有のキャラや表現は置き換える。

## 5. 代表例で共通の方針をつくる

最初の試作には、短い言葉と長い言葉、静かな感情と強い感情、形の違う原画を選ぶ。似た条件だけを選ぶと、その条件にだけ合うレイアウトになりやすい。

### 候補の作り方

- A案：全文がすぐ読める構成を優先。
- B案：表情や意味のある仕草がよく見える構成を優先。
- C案：文字とキャラの動きや輪郭の一体感を優先。

これは比較の切り口であり、A案で顔を隠してよい、B案で文字が読めなくてよいという意味ではない。すべての候補で原画保持・文言の正確さ・基本の読みやすさを満たす。

代表6〜8枚、各2〜3案は試作量の目安。依頼枚数、費用、対応機能に応じて減らす。最初から全40枚を多案生成する必要はない。文字組みを後から調整できる環境では、原画を再生成せず合成案を比較する。

### 比較で見ること

1. その言葉を、その感情で送る場面が想像できるか。
2. キャラの特徴と主要な表情が見えるか。
3. 小さく表示しても全文を読み取れるか。
4. 文字とキャラの間に不自然な隙間や重なりがないか。
5. 共通の書体や色の方針に合い、ほかの案と違いがあるか。

採用理由は「可愛いから」だけにせず、「二段にして全文が大きく読め、顔の横の空間を使えた」のように具体的に残す。判断を数値化する場合も、採点だけを検証の代わりにしない。

## 6. 文字と原画を合成する

環境が対応する場合、原画、文字、装飾、プレビュー用背景を分けて管理する。文字列、書体、位置、サイズ、行間、字間、縁取りなどを変更できる形で残すと、局所修正に使える。

### 調整の順序

1. 原画と指定文言に合うレイアウトを選ぶ。
2. 顔と文字を読める大きさに置く。
3. 意味が通る位置で改行する。
4. 文字とキャラの距離、字間、行間を整える。
5. 色、縁取り、必要な装飾を加える。
6. 出力サイズにした状態で見直す。

字数だけでサイズを決めない。同じ文字数でも、漢字とひらがな、書体、縦横の配置で密度が違う。文字を横に押し潰して収める処理は標準にせず、改行や配置で読みやすさを確保する。

縦書きでは長音符・句読点・英数字・記号の向き、弧状配置では文字の傾きと読み順を確かめる。単に1文字ずつ並べただけで自然に読めるとは限らない。

### 余白の扱い

通常静止画の外周約10pxという規格と、文字とキャラの間の空間は別に管理する。外周は、文字の縁取りや装飾も含む完成内容を基準にする。キャンバス全体だけでなく、実描画の範囲を見て配置する。

自動トリミングは、薄い線、淡い影、半透明の表現を誤って削る可能性も考える。元の特徴や意図した余白を見て確認し、使用した判定方法を記録する。

## 7. セットを制作し、一覧で見直す

採用した書体、色、縁取り、原画の見せ方を基準に残りを作る。各スタンプでは、その原画と文言に合うレイアウトを選ぶ。

一覧では、文字の位置、キャラと文字の大小関係、文言の用途、感情の強さが偏っていないかを見る。同じ構成の上限を機械的に決めるより、使う場面や原画に理由があるかを確認する。統一感が目的の作品では、同じ型を繰り返す判断も成立する。

並び順は、よく使う表現を探しやすくしつつ、似た見た目が続く箇所を点検する。公式の並び順解説も参考になるが、特定の位置の利用傾向を全端末・全作品に共通する保証にはしない。

参照：[LINE公式・ポイント7選](https://note.com/line_cm/n/nb64a789c6d30)（2022年9月9日）。

## 8. 検品と修正

[品質チェック](04_QUALITY_CHECKLIST.md) を使い、[REVIEW_LOG](../templates/REVIEW_LOG.md) に実施した内容を記入する。

- サイズ、形式、容量等は、出力ファイルを対象に確認する。
- 文言の指定データが正しくても、実際に描画した字が欠けたり潰れたりしていないかを見る。
- OCRや自動検査は補助に使う。読めること、顔が見えること、雰囲気が合うことまで自動で保証しない。
- 縮小率50%・25%などは内部比較の例。実際のLINEの表示寸法を示す数値ではない。
- 背景比較は最終出力を合成して確かめる。市松模様を背景透過そのものと混同しない。
- 不合格箇所だけを中心に修正し、関連するチェックをやり直す。

### 再確認する範囲の例

| 修正 | 再確認すること |
|---|---|
| 字間や行間を変えた | 全文の読みやすさ、文字切れ、隣接する絵との距離 |
| 縁取りを変えた | 背景での分離、字の内部、外周余白、文字同士の接触 |
| キャラを大きくした | 顔・手・固有の特徴、文字との重なり、外周余白 |
| 配置を変えた | 読み順、感情との一致、一覧での偏り |
| 書体を変えた | 全文字の描画、太さ、字間、記号、縮小時の判読 |

一度良くなった箇所を保ったまま修正を進める。既に確認済みの関係のない全工程を繰り返す必要はない。

## 9. 出力と報告

申請用まで依頼された場合は、通常静止画の公式規格でスタンプ本体、メイン画像、タブ画像、必要なZIPをそろえる。制作途中の候補・一覧・背景プレビューを提出用画像に混ぜない。

ファイル名の例は `01.png`、作業用は `01_candidate-a.png`、一覧は `preview/contact-sheet.png` のように、用途が判別できるものにする。これは制作管理の例であり、公式の命名規則と断定しない。アップロード時に要求される仕様はその時点の画面・公式案内で確認する。

報告には、次の内容を短く記す。

1. 作成したものと、その場所。
2. 採用したデザイン方針。
3. 実際に行った確認と、対象の版。
4. 未確認の項目と理由。
5. 次回に引き継ぐ判断基準。

未確認項目がある場合でも、できた部分を示す。納品、ユーザー確認、申請、審査通過、販売開始は別の状態として扱う。

## 10. 次の制作で改善する

ユーザーの感想と、採用・修正の理由から、短いルールを残す。

- このキャラでは、顔の横に二段で置くと長い文言が読みやすかった。
- この書体では、小さな濁点が潰れたので太さと縁取りを調整した。
- 静かな表現は、装飾がない案の方が原画と合っていた。

上記は記録の例であり、本リポジトリで既に実測した結果ではない。

販売後に統計が利用できる場合は、同じ期間の画像別送信数や利用者の意見も参考にする。少数で非表示の値をゼロと解釈しない。よく送られた理由には文言の用途、季節、配置など複数の要因があるため、デザインだけの因果と断定せず次の比較案に活かす。

参照：[LINE公式・売上と統計の活用](https://note.com/line_cm/n/nc9bde587ef40)、[公式マニュアル・アイテム詳細](https://linecreator-manual-ja.blog.jp/archives/17611365.html)。
